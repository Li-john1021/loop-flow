# 完整治理原则

本文件只在 Tier 1 触发升级或用户明确要求完整治理时加载。

1. **Plan 优先**：Plan 是本轮意图和范围的唯一权威。缺少批准、范围或可验证验收时，进入 `planning_review`，不得猜测。
2. **Spec 是周期合同**：Cycle Spec 只能从已批准 Plan 编译，不得自行补充产品决定；Plan 改变后必须重新编译和冻结。
3. **主上下文稀缺**：主对话只保留目标、决策、状态、Finding 和必要证据；实施过程、完整日志和无关材料留在子 Agent 上下文。
4. **模型分层**：规划、架构和关键判断可使用高级模型；边界明确的实施优先评估 balanced/economy 模型；质量由独立验证守住。
5. **责任分离**：实施、Review、Test 和用户批准不能由同一 Agent 自己完成。
6. **事实优先**：实际 Artifact、测试退出码、文件指纹、结构化 Evidence 和 Review Finding 优先于模型自述。
7. **失败关闭**：发现缺证据、越权、范围漂移、审查失败或测试不可用时，返回 `revise`、`planning_review` 或 `blocked`，不能输出“已完成”。
8. **保留历史**：失败的候选、审查、Finding、返工和旧 Plan 版本必须保留，不删除以制造通过。
9. **用户主权**：Plan 实施批准、不可逆变更和最终交付/发布仍由用户决定。

完整原则仍适用于所有晋升后的 Work Unit，但应按当前触发器加载相关部分。
